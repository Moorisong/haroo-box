# 하루상자 통합 영업 리드 수집 컨벤션

## 1. 실행 진입점
사용자가 “lead_collection_convention.md 지침대로 진행해”라고 요청하면 신규 리드 조사·검증·저장·재조회까지 명시적으로 승인한 것으로 해석한다. 문서 열람만으로 실행하지 않는다. 이메일·DM 등 발송은 승인 범위에 포함되지 않는다.
매 실행 시작 시 haroo-box dev 브랜치의 이 문서, 같은 디렉터리의 lead_collection_config.yaml 및 설정에 등록된 활성 채널 문서를 직접 조회한다. 사용자에게 문서 재첨부를 요구하지 않는다. 접근 불가 또는 설정 누락 시 추측하지 말고 구체적으로 보고한다.

## 2. 설정 및 우선순위
현재 요청의 명시적 조건 > 설정 파일 기본값 > 채널별 기본값 순으로 적용한다. 통합 실행에서는 기존 채널 문서의 매번 질문 규칙을 대체한다. 필수 조건이 모두 확정되면 질문이나 실행 전 재승인 없이 진행한다. 조건이 누락되거나 모순되면 필요한 사항만 한 번에 질문한다. 기본값은 이번 실행에만 적용하며 명시적 요청 없이 설정 파일을 수정하지 않는다.
채널별 공식성·활동·적합성·출처·저장·안전 규칙은 그대로 준수한다. 통합 문서의 공통 실행·채널 배정·중복 관리 규칙을 우선 적용하되 검증 기준을 완화하지 않는다.

## 3. 채널 확장
설정의 enabled: true 채널만 실행한다. 신규 채널은 전용 문서와 설정 항목을 추가하면 된다. 각 채널은 문서 경로, 대상 탭, 목표 건수, 우선순위, 검증 기준, 필수 열, 접촉 기록 열을 정의해야 한다. 비활성 채널도 기존 영업 DB에 데이터가 있다면 중복 및 접촉 제외 검사를 위해 읽는다. 미등록 탭에 영업 데이터가 있는지 메타데이터를 확인하고 판별이 불가능하면 저장을 보류한다.

## 4. 공통 실행 파이프라인
1. 설정 및 활성 채널 문서를 읽고 목표와 조건을 확정한다.
2. Google Sheets의 모든 등록 영업 채널 탭 전체 데이터, 실제 헤더, 발송·접촉 제외 기록을 조회한다. 접근 불가 시 신규 저장을 보류한다.
3. 타깃과 지역이 같은 채널은 공통 후보 풀을 사용한다. 조건이 다르면 해당 조건별로 후보 풀을 나눈다. 초기 후보 목표는 합산 신규 목표의 약 2배 이상이며 탈락률에 따라 확장한다.
4. 공식 단체명, 지역, 공식 도메인, 최근 12개월 활동 근거, 서비스 적합성을 한 번 조사하고 재사용한다. 각 채널의 추가 필수 검증은 별도로 수행한다. 공통 검증 결과가 해당 채널 기준을 충족하지 않으면 추가 검증한다.
5. 전체 기존 DB 및 이번 후보를 비교하여 중복·접촉 이력·수신 거부를 검사한다. 정규화한 단체명+지역, 공식 도메인, 공식 연락처 연결 근거를 함께 사용한다. 공유 도메인만으로 동일성을 단정하지 않는다. 불명확한 후보는 보류한다.
6. 검증된 채널 중 목표가 남은 채널에 후보를 배정한다. 한 채널만 적합하면 그 채널에 우선 배정하고, 복수 채널이 적합하면 설정 우선순위와 채널별 부족분을 고려한다. 동일 단체는 기본적으로 한 채널에만 배정한다. 기존 접촉 기록이 있거나 접촉 제외된 단체는 제외한다. 사용자 명시 승인 없는 교차 등록은 금지한다.
7. 채널별 목표를 독립적으로 관리한다. 목표가 찬 채널에는 추가 저장하지 않고 부족 채널의 검색 전략을 확장한다.
8. 후보 탐색과 검증은 도구가 허용하는 범위에서 병렬화할 수 있으나 저장은 단일 조정자가 순차 배치로 수행한다. 독립 작업자가 동시에 저장하지 않는다. 각 배치 직전 전체 채널 및 이번 실행의 예약·저장 후보를 재검사한다. 다른 외부 실행과의 완전한 동시성 방지는 보장할 수 없으므로 충돌 발견 시 중단하고 보고한다.
9. 각 채널 문서의 실제 열 매핑에 따라 20~50건 또는 안정적인 크기로 신규 행만 추가한다. 기존 데이터·수식·서식·접촉 기록을 변경하지 않는다. 저장 후 실제 행과 전체 채널 중복 여부를 재조회한다. 실패 시 저장 상태부터 확인한 후 중복 없이 재시도한다.
10. 목표 달성 또는 실제 실행 한계까지 반복한다. 검증 기준을 낮추거나 미확인 정보를 생성하지 않는다.

## 5. 완료 및 재개
저장 후 재조회에 성공한 신규 리드만 실적으로 인정한다. 채널별 요청·후보·검증·저장·재조회·부족 건수, 제외 사유, 신규 행 범위, 출처 확인 및 기존 데이터 보존 여부를 통합 보고한다. 실제 중단 시 구체적 사유, 마지막 정상 저장 행, 남은 목표, 조사 범위, 미저장 검증 후보 및 재개 전략을 남긴다. 재개 요청은 기존 저장분을 중복 집계하지 않는다. 독립적인 신규 실행은 설정 목표를 새로 적용한다.
일반 중간 보고는 최소화하되 실제 차단·권한 문제는 보고한다. 도구 호출·시간 한도를 늘릴 수 없으며 목표 달성이나 실제 병렬 실행을 보장하지 않는다.

## 6. 안전
공개 공식 업무용 연락처만 조사한다. 접근 제한·이용약관·개인정보 및 관련 법규를 준수한다. 차단 우회, 연락처 추측, 이메일·DM 작성 및 발송, 자동 팔로우·댓글은 하지 않는다. 문서 구축 자체는 수집 실행이나 시트 수정 승인이 아니다.
