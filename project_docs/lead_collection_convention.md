# 하루상자 리드 수집 공통 컨벤션 v3.1

## 실행 방식: 한 대화에 한 탭
- `cold_email_lead_collection_convention.md 지침대로 진행해` → email 탭만 수집 및 저장.
- `cold_ig_lead_collection_convention.md 지침대로 진행해` → ig 탭만 수집 및 저장.
- 위 명령은 공통 문서와 선택 채널 문서의 기본값을 적용한 명시적 실행 승인이다. 추가 질문이나 재승인 없이 진행한다. 단순 문서 열람은 실행 승인이 아니다.
- `lead_collection_convention.md 지침대로 email 탭만 진행해` 또는 ig 탭만 진행해도 동일하게 실행한다. 공통 문서만 지정하고 탭을 지정하지 않으면 어느 탭인지 한 번만 질문한다. 모든 탭 통합 실행은 기본 지원하지 않는다.
- 매 실행 GitHub Moorisong/haroo-box dev 브랜치에서 공통 문서와 선택 채널 문서만 읽는다. 다른 채널의 조사 지침은 읽거나 실행할 필요가 없다.
- 사용자 명시 조건 > 문서 기본값. 목표는 선택 채널 문서에 명시된 신규 저장 및 재조회 성공 건수다. 다른 채널 목표를 합산하지 않는다.
- 별도 채팅에서 순차 실행을 권장한다. 동시에 실행하면 외부 작업 간 원자적 중복 방지를 보장할 수 없다. High 모드는 권장하되 실행 시간·검색 한도를 보장하지 않는다.

## 기본 수집 조건
- 타깃: 교회, 청소년부
- 지역: 아시아 (대한민국 제외)
- 언어: 영어
- 홍보 서비스: 하루상자 어드벤트 캘린더
- 적합성: 크리스마스·연말 참여형 행사, 청소년·가족 프로그램
- 영업 DB: https://docs.google.com/spreadsheets/d/1A6D4en55_K8jFBy8h57ar8UV3gXqbWF7mgOQ9ER5SQA/edit
- 신규 저장 및 재조회 자동 실행, 발송 금지. 목표 건수와 열 매핑은 선택 채널 문서에 따른다.

## 공통 품질 및 중복 기준
- 공개 공식 업무용 연락처만 수집. 공식 단체명, 국가/지역, 공식 연락처 출처, 최근 12개월 내 날짜가 명시된 공식 활동 근거, 서비스 적합성 근거, 검증일을 확보한다. 미래 일정만으로 최근 활동을 단정하지 않는다. 날짜 없는 소개·검색 색인일은 활동 근거가 아니다.
- 공식 이메일/IG 확인과 실제 수신 가능성은 별개다. 확인되지 않은 정보는 추측하지 않는다.
- 전체 영업 탭의 기존 데이터와 발송 이력을 읽고 정규화 인덱스를 구축한다. 다른 탭은 읽기 전용이다. 단체명+지역, 공식 도메인, 연락처/계정 등을 비교한다. 공유 도메인만으로 중복 단정 금지. 기존 타 채널의 동일 단체도 제외하며 독립 지점은 공식 근거가 있을 때만 구분한다. 접촉 이력·수신 거부·접촉 제외를 확인한다. 필수 중복 검사 불가 시 저장 보류.
- 공개 자료의 접근 제한, 약관, 개인정보 보호, 합리적인 요청 속도를 준수한다. 이메일/DM 작성·발송, 자동 팔로우·댓글 금지.

## 실행 순서
1. 설정과 선택 채널 목표 확정. 실제 스프레드시트 메타데이터, 전체 영업 탭 헤더 및 기존 사용 범위 조회. 실제 마지막 데이터 행 확인. 새 탭은 전용 채널 문서에 탭과 열 매핑이 명시된 경우만 수집 대상으로 선택한다.
2. 기존 DB를 한 번 읽어 중복 인덱스를 재사용한다. 후보 탐색은 선택 채널에만 집중한다. 국가·도시·행사 키워드를 묶어 검색하고 기존 중복을 먼저 제거한 뒤 공식 연락처·활동·적합성을 검증한다.
3. 초기 후보는 목표의 약 2배를 권장하되 탈락률에 따라 확장한다. 전체 후보 확보 전에도 검증 완료 묶음을 저장할 수 있다. 검색/검증은 도구가 허용하는 범위에서 배치 처리한다.
4. 선택 채널 문서에 명시된 신규 데이터 열에만 저장한다. 현재 email/ig는 A:F만 쓰고 G:I는 발송 기록으로 보호한다. 지정된 증빙 메모 열(현재 F)에 공식 연락처 출처 URL, 활동 날짜/URL, 적합성 근거, 검증일을 기록한다. 메모 기능이 불가하면 추적 가능한 검증 로그를 제공하고 제한을 보고한다. 실제 헤더가 달라 안전한 매핑을 확정할 수 없으면 저장 보류. 기존 행·헤더·서식·수식·발송 기록은 변경하지 않는다.
5. 검증 완료 후보를 5~20건 단위로 저장한다. 실제 종료 직전에는 검증된 잔여 소량도 저장 가능하다. 배치 직전 전체 영업 탭의 신규 변경분과 중복·접촉 이력 및 대상 마지막 행을 재확인한다. 변경분 확인이 불가능하면 필요한 범위를 다시 읽는다. 저장 후 신규 값, 메모, 발송 기록 열 보존 및 중복 여부를 재조회한다. 실패 시 실제 저장 상태부터 확인하고 중복 없이 재시도한다.
6. 목표 미달이면 국가·도시·검색어를 변경하여 반복한다. 첫 검색, 첫 배치, 소수 성공, 단순 중복 증가만으로 종료하지 않는다. 실제 도구 한도, 권한, 접근 제한, 합리적인 탐색 확장 후 후보 부족 등 관측된 사유로만 부분 종료한다. 품질 기준을 낮추지 않는다.
7. 최종 보고: 선택 탭, 목표, 후보 수, 제외 사유별 건수(미집계는 명시), 검증·저장·재조회 성공 수, 신규 행 범위, 부족분, 기존 데이터/발송 기록 보존, 출처 기록 여부, 실제 중단 사유와 재개 범위. 미달은 부분 완료로 표시한다. 일반 중간 보고는 최소화한다.

## 확장
새 채널은 탭·목표·열 매핑을 명시한 전용 컨벤션을 추가하고 해당 문서명 한 줄로 실행한다. 기존 채널의 수집 규칙을 변경할 필요는 없다.
