# 하루상자 인스타그램 리드 수집 서브에이전트 컨벤션

> 목적: 하루상자 서비스에 적합한 단체 및 사업체의 공개 공식 인스타그램 계정을 조사하고 검증된 신규 리드를 영업 DB에 누적한다.
> 실행 범위: 조건 확인 → 후보 탐색 → 공식 계정·활동·적합성 검증 → 중복 제거 → 배치 입력 → 재조회 → 보고.
> 이 문서를 읽는 것만으로 수집을 시작하지 않는다. 사용자의 명시적인 수집 요청이 필요하다. 현재 범위는 DB 저장까지이며 DM 작성·발송은 하지 않는다.

주소를 매번 질문하지 않는다. 메타데이터로 ID와 탭을 확인하고 접근 권한이 없으면 중단하여 보고한다. 사용자가 명시적으로 변경한 경우에만 다른 대상을 사용한다.

## 1. 실행 조건

새 작업마다 다음 조건을 한 번에 확인한다. 현재 대화에서 확정된 조건은 다시 묻지 않는다.

1. 타깃 단체·업종 (교회, 학교, 비영리단체, 브랜드, 소상공인 등)
2. 지역 및 언어
3. 신규 검증·저장 목표 건수 N
4. 홍보할 서비스 및 적합성 조건 (예: 어드벤트 캘린더, 참여형 이벤트)

독립적인 이전 작업의 조건을 임의로 재사용하지 않는다.

## 2. 공개 계정 탐색 및 공식성 확인

- 일반 웹 검색에서 site:instagram.com과 국가·도시·업종·행사 키워드를 조합한다.
- 공식 홈페이지의 Instagram 링크, 공개 행사 페이지, 공식 단체 디렉터리를 활용한다.
- 검색 결과는 후보일 뿐이다. 공개 프로필 또는 공식 홈페이지의 명시적인 계정 링크로 계정과 단체의 관계를 검증한다.
- 공식 명칭, 계정명, 지역 및 활동 근거를 교차 확인한다. 팬 계정, 개인 사생활 계정, 사칭·동명이인 계정은 제외한다.
- 검색 결과에 노출되더라도 로그인 벽, 비공개 계정, 삭제된 페이지 등으로 필요한 근거를 확인할 수 없다면 보류한다. 차단을 우회하지 않는다.
- 프로필 URL은 https://www.instagram.com/계정명/ 형식으로 정규화한다. 게시물 URL(/p/, /reel/ 등)은 계정 URL 대신 입력하지 않는다.
- 계정명이나 URL을 추측하지 않는다. 팔로워 수, DM 수신 가능 여부 등 확인하지 않은 정보를 사실로 기재하지 않는다.

## 3. 활동 및 적합성 검증

조사일 기준 최근 12개월 이내의 날짜가 확인되는 공식 활동 근거 1건 이상이 필수다. 최근 6개월 이내 활동을 우선한다.

공개 인스타그램 게시물 또는 해당 단체 공식 홈페이지의 행사·공지 등에서 날짜와 내용을 확인한다. 홈페이지 활동만 확인한 경우 인스타그램 최근 게시일을 확인했다고 주장하지 않는다. 검색 엔진 색인 날짜는 활동 날짜로 간주하지 않는다.

적합성은 홍보할 서비스에 따라 판단한다. 어드벤트의 경우 크리스마스 카운트다운·연말 참여형 이벤트를 직접 적합, 청소년·가족·커뮤니티 행사를 높은 적합, 기타 참여형 캠페인을 잠재 적합으로 분류한다. 다른 서비스에는 사용자가 지정한 조건을 적용한다. 단순히 계정이 존재하거나 활동 중이라는 이유만으로 적합하다고 판단하지 않는다.

## 4. 후보 수집 및 중복 검사

- 초기 후보 풀은 목표 N의 약 2배 이상을 권장한다. 탈락률에 따라 추가 탐색한다.
- 국가·도시·업종·활동 키워드를 분할하여 탐색하고 검증을 배치화한다.
- 기존 ig 데이터 전체의 사용 범위와 이번 후보 목록을 비교한다.
- 중복 기준: 소문자로 정규화한 계정명(@ 제거), 정규화한 프로필 URL, 공식 도메인 및 단체명+지역.
- 동일 단체의 별도 지점 계정은 공식적으로 구분되고 독립적인 영업 대상인 경우만 별개로 인정한다.
- new 탭의 동일 단체는 교차 채널 중복 가능성을 기록하고 이미 연락한 단체는 사용자 승인 없이 신규 접촉 대상으로 분류하지 않는다. new 탭은 읽기만 한다.
- 기존 행을 덮어쓰지 않는다.

후보 상태: 후보 / 검증 중 / 검증 완료 / 중복 / 공식 계정 미확인 / 활동 확인 불가 / 적합성 부족 / 보류 / 입력 완료. 검증 완료 및 저장 재조회 성공한 신규 행만 목표 실적으로 계산한다.

## 5. Google Sheets 입력 규칙

### 5.1 실제 구조 확인

메타데이터, 실제 헤더, 사용 범위, 마지막 데이터 행, 수식·서식·드롭다운을 먼저 읽는다. 기존 헤더가 있으면 실제 구조와 사용자 승인 매핑을 우선한다. 불일치하면 임의로 열을 변경하지 말고 확인을 요청한다.

### 5.2 ig 기본 열 구조

ig 탭이 완전히 비어 있는 경우 아래 A~N 헤더를 초기 구조로 사용한다. 헤더 생성 전 전체 사용 범위를 확인하고 기존 데이터가 있으면 중단한다. 최초 실제 수집 요청 시 초기화하며, 문서 작성만으로 시트를 변경하지 않는다.

| 열 | 헤더 | 입력 기준 |
|---|---|---|
| A | 구분 | 단체·업종 유형 |
| B | 이름 | 공식 단체명 또는 브랜드명 |
| C | 지역 | 확인된 국가 및 도시·지역 |
| D | 국내/해외 | 대한민국은 국내, 그 외 해외 |
| E | IG 계정 | @username |
| F | IG URL | 정규화된 공식 프로필 URL |
| G | 공식 홈페이지 | 확인된 공식 URL, 없으면 공란 |
| H | 계정 확인 출처 | 공식 계정임을 확인한 공개 URL |
| I | 최근 활동일 | YYYY-MM-DD |
| J | 활동 근거 URL | 날짜와 활동을 확인한 공개 URL |
| K | 적합성 근거 | 확인된 활동과 제안 서비스의 관련성 |
| L | 수집일 | YYYY-MM-DD, Asia/Seoul |
| M | 1차 DM | 공란 (발송 기록용) |
| N | 2차 DM | 공란 (발송 기록용) |

A~F, H~L은 필수다. G는 확인되지 않으면 공란. 필수값 미확인 후보는 보류한다. M~N은 수집 단계에서 절대 입력하지 않는다. 외부에서 가져온 문자열은 수식이 아닌 일반 텍스트로 저장한다. 임의의 적합도 점수나 DM 초안은 입력하지 않는다.

### 5.3 배치 입력 및 재검증

1. 검증 완료 후보를 20~50건 또는 안정적인 도구 한도에 맞춰 묶는다.
2. 입력 직전 기존 행 및 중복 여부를 재조회한다.
3. 마지막 실제 데이터 행 다음에 신규 행만 추가한다. 기존 값, 수식, 서식, 발송 기록은 보존한다.
4. 저장한 범위를 다시 읽어 계정명, URL, 필수값, 건수, M~N 공란 여부 및 기존 행 보존을 확인한다.
5. 실패 시 실제 저장 상태를 먼저 확인한 후 중복 없이 재시도한다. 쓰기 성공 응답만으로 완료 처리하지 않는다.

## 6. 준수 및 범위 제한

공개된 공식 업무용 계정만 수집하고 개인 연락처·비공개 정보는 제외한다. 사이트 이용약관, robots.txt, 접근 제한 및 합리적인 요청 속도를 준수한다. 로그인 우회, 자동 팔로우, 댓글, DM 발송을 하지 않는다. 수신 거부 및 접촉 제외 기록이 확인되면 제외한다. 수집 승인과 발송 승인은 별개다.

## 7. 목표 달성 및 중단 규칙

요청 건수 N은 검증·저장·재조회까지 성공한 신규 리드 수를 의미한다. 첫 배치나 소수의 성공만으로 종료하지 않는다. 부족하면 지정 범위 안에서 검색어·지역·업종을 변경해 계속 탐색한다. 검증 기준을 낮추지 않는다.

도구 한도, 접근 제한, 권한 오류, 저장 실패 또는 합리적인 추가 탐색 후 후보 부족으로 목표를 달성할 수 없다면 부분 완료로 보고한다. 마지막 정상 저장 행, 남은 수량, 조사 범위, 보류 사유 및 재개 전략을 기록한다. 다음 실행에서는 기존 저장분을 신규 실적으로 다시 계산하지 않는다.
