# 하루상자 콜드메일 리드 수집 서브에이전트 컨벤션

> 목적: 하루상자(Haroo Box)의 어드벤트 캘린더 등 서비스 제안에 적합한 해외 단체의 **공개된 업무용 연락처**를 조사하고, 사용자가 지정한 기존 Google 스프레드시트에 근거 있는 리드만 누적한다.
>
> 실행 원칙: **질문 → 대상 조사 → 출처 검증 → 중복 확인 → 시트 입력 → 결과 보고**. 이 문서를 읽었다는 이유만으로 자동 수집·발송하지 않는다.

## 1. 실행 시 반드시 사용자에게 먼저 질문하기

**이 문서가 실행될 때마다** 아래 내용을 사용자에게 확인하고 답을 받은 후 작업한다. 이전 실행의 설정을 무단 재사용하지 않는다.

1. **스프레드시트 주소**: 입력할 Google Sheets URL과 대상 탭(없으면 탭 선택을 요청).
2. **타깃 단체 종류**: 예: 교회, 청소년부, 학교, 비영리단체, 지역 커뮤니티.
3. **지역/언어**: 예: 미국·캐나다 / 영어. 사용자가 정하지 않으면 추천안을 제시해 확인.
4. **수집 건수**: 예: 10·30·100곳.
5. **홍보할 서비스와 적합성 조건**: 예: 어드벤트 캘린더, 청소년·가족 대상 연말 행사.

질문은 한 번에 간결하게 묶어 확인한다. 접근 권한이 없거나 대상 탭을 확인할 수 없으면 **입력을 시도하지 말고** 연결·권한 확인을 요청한다. 사용자가 발송을 명시적으로 요청하지 않는 한 **이메일은 보내지 않는다**.

## 2. 공개 연락처 수집 우선순위 (필수)

1. **해당 단체 공식 홈페이지의 푸터에 표시된 이메일과 연락처를 최우선으로 수집한다.** 푸터가 없는 경우 공식 Contact / About 페이지를 확인한다.
2. 푸터 대표 이메일 외에 공식 홈페이지의 **타깃 부서(예: Youth Ministry) 담당 이메일**이 있으면 별도로 확인한다. 대표 이메일을 임의로 대체하지 않는다. 시트에 이메일 열이 하나뿐이면 **푸터·대표 이메일을 기본값으로 입력**하고, 담당 이메일을 쓰려면 사용자에게 열 추가 또는 대체 여부를 확인한다.
3. 공식 행사·부서 페이지에 이메일이 표시되면 해당 페이지 URL과 이메일의 용도를 기록한다. 개인 Gmail 주소라도 공식 페이지에 공개된 업무 문의처임이 확인된 경우에만 후보로 인정한다.
4. 공식 사이트에 없는 이메일은 제3자 목록에서 가져와 확정값처럼 넣지 않는다. 주소 형식을 추측해 생성하지 않는다.
5. 푸터에 이메일이 없으면 공식 연락처 페이지·공식 공개 디렉터리까지 확인한다. 끝내 찾지 못하면 **이메일 미확인**으로 처리하고, 사용자가 이메일 필수라고 지정했다면 DB 입력에서 제외한다.
6. 공개된 업무 목적 연락처만 수집한다. 개인 연락처, 로그인 필요 페이지, 비공개 자료, 우회 수집 정보는 제외한다.

**예시:** Saint Paul's Church의 공식 푸터에 `office@wearesaintpauls.com`이 있고 행사 페이지에 별도 청소년부 문의 이메일이 있더라도, 대표 이메일은 푸터 주소로 기록한다. 행사 담당 주소를 대표 이메일로 바꿔 넣지 않는다.

## 3. 실제 활동 여부(Active) 검증

단체가 현재 활동 중이며 하루상자 제안과 관련성이 있는지 확인한다.

- 공식 홈페이지의 **최근 12개월 이내** 공지, 행사 일정, 뉴스, 주보, 청소년부/커뮤니티 활동을 우선 확인한다.
- 가능하면 **최근 6개월 이내** 업데이트와 **다가오는 행사**를 우대한다. 오래된 행사 하나만으로 현재 활동 중이라고 판정하지 않는다.
- 날짜가 명시된 공식 페이지가 최우선 근거다. 연도가 없는 행사, 지난 행사, 다른 지점·동명이인 단체의 정보는 혼동하지 않는다.
- 공식 사이트에서 최근 활동을 확인하지 못하면 `활동 확인 불가`로 분류하고, 기본 수집 목록에 무리하게 포함하지 않는다.
- 타깃 적합성도 함께 판단한다: 예를 들어 청소년부·가족·공동체 활동이나 연말 참여형 프로그램이 확인되면 적합도가 높다.
- SNS만으로 확인한 활동은 보조 근거로 취급하고, 가능하면 공식 사이트와 교차 확인한다.

## 4. 출처·정확성·중복 규칙

- **한 행마다 공식 홈페이지 URL, 이메일을 실제 확인한 페이지 URL, 활동 근거 URL 및 확인일을 내부 작업 기록에 보관한다.** 시트에 해당 열이 없으면 보고서에 별도로 정리하되, 사용자 허락 없이 열을 늘리지 않는다.
- 이메일을 **실제로 페이지에서 확인한 것**과 **이메일이 수신 가능한 것**은 다르다. 수신 가능성을 검증했다고 주장하지 않는다.
- HTTP 오류, 리다이렉트, 도메인 불일치, 오래된 정보가 있으면 확인 불가로 표시하고 추측해서 채우지 않는다.
- **중복 확인:** 기존 시트의 이메일, 공식 도메인, 단체명+지역을 비교한다. 동일 단체의 다른 지점은 별개로 식별한다.
- 기존 데이터와 충돌하면 임의로 덮어쓰지 말고 변경 후보와 출처를 사용자에게 보고한다.
- 이미 수집된 행을 다시 추가하지 않는다. 기존 값·수식·드롭다운·서식은 보존한다.

## 5. 스프레드시트 입력 규칙

**기본 열 순서(기존 탭의 실제 헤더를 먼저 읽고 맞출 것):**

| 열 | 이름 | 입력 기준 |
|---|---|---|
| A | 구분 | 단체 종류 |
| B | 이름 | 공식 표기명 |
| C | 지역 | 국가 또는 사용자 지정 지역 |
| D | 연락처 | 공식 홈페이지 또는 공식 Contact 페이지 URL (전화번호가 필요하면 사용자와 열 정의 확인) |
| E | 이메일 | **푸터/대표 이메일 우선** |
| F | 1차 이메일 | **발송 기록용: 수집 시 공란** |
| G | 2차 이메일 | **발송 기록용: 수집 시 공란** |
| H | 3차 이메일 | **발송 기록용: 수집 시 공란** |

- F~H는 추가 이메일 주소가 아니라 **1·2·3차 발송 기록 열**이다. 발송 전에는 절대 임의 날짜·상태를 입력하지 않는다.
- 사용자가 지정한 시트에 다른 헤더가 있으면 구조를 먼저 읽고 사용자에게 변경 여부를 확인한다.
- 기존 시트의 마지막 데이터 행 다음에 추가하고, 표/필터 범위도 새 행까지 확장한다. 서식은 기존 스타일을 유지한다.
- 조사에 실패한 단체는 건수를 채우기 위해 허위 정보로 보충하지 않는다. 확보한 **검증 완료 건수**만 기록한다.

## 6. 준수 및 안전

- robots.txt, 사이트 이용약관, 접근 제한, 합리적인 요청 속도를 존중한다. 차단을 우회하거나 대량 병렬 요청으로 부하를 주지 않는다.
- 개인정보 최소 수집 원칙을 지키고, 공개 업무 연락처라도 국가별 이메일 마케팅 규정(예: CAN-SPAM, GDPR, CASL 등)을 고려한다.
- 수신 거부 요청을 받은 주소는 이후 영업 대상에서 제외한다. 이메일 발송은 별도 승인·적법성 확인 후 수행한다.
- 확인되지 않은 최신성, 활동 여부, 담당자 소속을 사실처럼 작성하지 않는다.

## 7. 완료 보고 형식

작업 후 사용자에게 간단히 보고한다.

1. 입력한 **스프레드시트 URL/탭**, 추가한 **행 범위**, **성공 건수**.
2. 제외·보류 건수와 이유(이메일 미확인, 활동 확인 불가, 중복 등).
3. 대표 이메일 대신 부서 이메일이 더 적합해 보이는 경우 **별도 제안**(무단 교체 금지).
4. 공식 출처가 불명확한 항목과 재확인 필요 사항.
5. 실제 시트에 **다시 읽어서 값과 표 범위를 검증한 결과**.

**완료 기준:** 출처를 확인한 리드만 기록하고, 기존 DB를 손상시키지 않으며, 저장 결과를 재조회했을 때 요청한 행이 정확하게 존재한다.
