# 하루상자 콜드메일 리드 수집 서브에이전트 컨벤션

> **목적:** 하루상자(Haroo Box)의 어드벤트 캘린더 등 서비스 제안에 적합한 해외 단체의 **공개된 업무용 연락처**를 대량으로 조사하고, 아래에 고정된 기존 Google 스프레드시트에 검증된 신규 리드만 누적한다.
>
> **실행 원칙:** 질문 → 대량 후보 수집 → 공식 출처 검증 → 중복 제거 → 배치 입력 → 저장 재검증 → 최종 보고
>
> **핵심 목표:** 정확성과 준수 원칙을 유지하면서, 사용자가 지정한 신규 리드 수량을 가능한 한 한 번의 실행에서 달성한다.
>
> **중요:** 이 문서를 읽었다는 이유만으로 자동 수집하거나 이메일을 발송하지 않는다. 수집 작업은 사용자가 명시적으로 실행을 요청한 경우에만 수행한다.

## 1. 실행 시 반드시 사용자에게 먼저 질문하기

**이 문서가 새로운 수집 작업에 적용될 때마다** 다음 4가지 조건을 사용자에게 확인한다.

1. **타깃 단체 종류:** 교회, 청소년부, 학교, 비영리단체, 지역 커뮤니티 등.
2. **지역/언어:** 예: 동남아시아 전체 / 영어.
3. **수집 건수:** 예: 10·30·50·100곳.
4. **홍보할 서비스와 적합성 조건:** 예: 어드벤트 캘린더, 청소년·가족 대상 연말 참여형 행사.

질문은 한 번에 간결하게 묶어 확인한다.

단, **현재 대화에서 이미 4가지 조건이 명확히 확정되어 있고 사용자가 같은 작업의 계속 실행을 요청했다면 다시 질문하지 않는다.** 사용자가 변경한 조건만 갱신한다.

이전의 독립적인 작업에서 사용한 설정은 사용자 확인 없이 무단 재사용하지 않는다.

접근 권한이 없거나 대상 탭을 확인할 수 없으면 입력을 시도하지 않고 연결·권한 확인을 요청한다.

**사용자가 발송을 명시적으로 요청하지 않는 한 이메일은 절대 보내지 않는다.**

## 2. 공개 연락처 수집 우선순위

### 2.1 공식 홈페이지 우선

1. **해당 단체 공식 홈페이지의 푸터에 표시된 대표 이메일과 연락처를 최우선으로 수집한다.**
2. 푸터에 이메일이 없으면 공식 Contact / About 페이지를 확인한다.
3. 공식 행사·부서 페이지의 이메일은 별도로 확인하고 해당 이메일의 용도를 기록한다.
4. 공식 홈페이지에 없는 이메일을 제3자 디렉터리에서 가져와 검증 완료 값처럼 입력하지 않는다.
5. 주소 형식을 추측하거나 생성하지 않는다.
6. 로그인 필요 페이지, 비공개 자료, 우회 수집 정보는 제외한다.

### 2.2 대표 이메일과 부서 이메일 구분

대표 이메일 외에 청소년부, 교육부, 행사 담당 부서의 이메일이 확인되면 별도로 기록한다.

**대표 이메일을 부서 이메일로 임의 대체하지 않는다.**

시트에 이메일 열이 하나뿐이라면 대표 이메일을 기본값으로 입력한다. 부서 이메일만 확인된 경우에는 기존 승인된 입력 정책에 따라 처리하되, 대표 이메일로 잘못 표시하지 않는다.

개인 Gmail 주소라도 단체 공식 홈페이지에 공개된 업무 문의처임이 확인된 경우에만 후보로 인정한다.

### 2.3 이메일 미확인 처리

공식 홈페이지, Contact 페이지, 공식 공개 디렉터리에서 이메일을 찾지 못하면 `이메일 미확인`으로 분류한다.

이메일이 필수 조건이라면 해당 단체를 최종 입력 대상에서 제외한다.

## 3. 실제 활동 여부(Active) 및 적합성 검증

### 3.1 최근 활동 기준

단체가 현재 활동 중인지 확인하기 위해 **조사일 기준 최근 12개월 이내의 공식 활동 근거 1건 이상**을 요구한다.

인정 가능한 근거:

- 공식 홈페이지의 날짜가 명시된 행사 일정
- 최근 공지사항, 뉴스, 블로그 게시물
- 교회 주보 및 청소년부 활동
- 학교·비영리단체의 프로그램 운영 공지
- 공식 연간 보고서 또는 활동 보고서
- 공식 SNS의 날짜가 확인되는 활동 게시물

가능하면 최근 6개월 이내 활동과 다가오는 행사를 우선한다.

**날짜가 없는 홈페이지 소개만으로 최근 활동을 확인했다고 판단하지 않는다.**

연도가 없는 행사, 오래된 행사, 다른 지점이나 동명이인 단체의 활동을 혼동하지 않는다.

SNS는 보조 근거로 활용하고, 가능하면 공식 홈페이지와 교차 확인한다.

최근 활동을 확인할 수 없다면 `활동 확인 불가`로 분류하고 최종 입력에서 제외한다.

### 3.2 하루상자 적합성 우선순위

**1순위 — 직접 적합**

- 어드벤트 캘린더
- 크리스마스 카운트다운
- 연말 참여형 이벤트
- 청소년·가족 대상 크리스마스 프로그램

**2순위 — 높은 적합성**

- 청소년부 및 어린이 교육 프로그램
- 가족·공동체 행사
- 크리스마스 기부 및 자원봉사 캠페인

**3순위 — 잠재 적합성**

- 청소년센터
- 지역 커뮤니티
- 교육기관
- 비영리단체의 참여형 캠페인

단순히 최근 활동이 있다는 이유만으로 적합하다고 판단하지 않는다.

최근 활동은 **현재 운영 여부**, 적합성은 **하루상자를 제안할 실질적인 이유**를 판단하는 별도 기준이다.

## 4. 대량 후보 수집 파이프라인

**대량 수집은 개별 단체를 하나씩 검색하고 즉시 입력하는 방식이 아니라, 후보를 먼저 확보하고 일괄 검증하는 방식으로 진행한다.**

### 4.1 목표에 따른 후보 풀 확보

사용자가 요청한 신규 검증 리드 수량을 N이라고 정의한다.

초기 후보 확보 목표는 다음과 같다.

| 신규 검증 목표 | 초기 후보 확보 목표 |
|---|---|
| 10건 | 20건 이상 |
| 30건 | 60건 이상 |
| 50건 | 100건 이상 |
| 100건 | 200건 이상 |

초기 후보 풀은 최종 저장 수량이 아니다.

중복, 이메일 미확인, 최근 활동 미확인, 적합성 부족 등으로 탈락할 가능성을 고려해 **목표의 약 2배 이상**을 우선 확보한다.

후보 탈락률이 높으면 추가 후보를 계속 수집한다.

### 4.2 검색 범위 분할

검색 범위를 다음 차원으로 분할한다.

**국가별**

사용자가 지정한 지역 내 국가를 나누어 조사한다.

예: 아시아 전체라면 싱가포르, 필리핀, 말레이시아, 인도네시아, 태국, 베트남, 인도, 홍콩, 대만, 일본 등.

**단체 유형별**

- 교회 및 종교 공동체
- 학교 및 교육기관
- 청소년센터
- 비영리단체
- 지역 커뮤니티
- 아동·가족 지원기관

**활동 유형별**

- Advent Calendar
- Christmas Event
- Youth Ministry
- Children's Program
- Family Event
- Community Outreach
- Charity Campaign
- Holiday Giving
- Volunteer Program

동일한 검색어만 반복하지 않고 국가·지역·단체 유형·활동 키워드를 조합해 검색한다.

### 4.3 검색 효율화

1. 여러 검색어를 묶어 후보를 탐색한다.
2. 검색 결과에서 공식 홈페이지 후보를 먼저 확보한다.
3. 후보의 단체명, 국가, 공식 도메인을 임시 목록으로 정리한다.
4. 기존 DB와 1차 중복 검사를 수행한다.
5. 중복되지 않는 후보에 대해 이메일과 최근 활동을 검증한다.
6. 검증을 통과한 후보만 최종 입력 목록으로 이동한다.

검색과 검증은 가능한 범위에서 병렬화하되, 사이트별 접근 제한과 합리적인 요청 속도를 준수한다.

**대량 수집은 요청을 무제한 병렬 실행한다는 의미가 아니다.**

### 4.4 후보 상태 관리

모든 후보는 다음 상태 중 하나로 분류한다.

- `후보`: 공식 홈페이지 발견, 검증 전
- `검증 중`: 이메일·최근 활동·적합성 확인 중
- `검증 완료`: 모든 필수 조건 통과
- `중복`: 기존 DB 또는 이번 실행 후보와 중복
- `교차 채널 중복`: 상대 탭에 동일 단체가 이미 존재
- `이메일 미확인`: 공식 업무용 이메일을 확인하지 못함
- `활동 확인 불가`: 최근 12개월 활동 근거 부족
- `적합성 부족`: 하루상자 활용 가능성이 낮음
- `보류`: 출처 불일치 또는 추가 확인 필요
- `입력 완료`: Google Sheets 저장 및 재조회 성공

**후보, 검증 중, 보류 상태는 목표 실적에 포함하지 않는다.**

## 5. 출처·정확성·중복 검증

### 5.1 리드별 필수 검증 정보

각 리드에 대해 다음 정보를 확보한다.

1. 단체 공식 명칭
2. 국가 및 지역
3. 단체 유형
4. 공식 홈페이지 URL
5. 공개 업무용 이메일
6. 이메일을 실제 확인한 공식 페이지 URL
7. 최근 활동을 확인한 공식 페이지 URL
8. 최근 활동 날짜
9. 조사·검증 날짜
10. 하루상자 적합성 판단 근거

**한 행마다 이메일 출처와 활동 근거를 추적할 수 있어야 한다.**

시트에 해당 열이 없다면 별도의 내부 작업 기록에 보관하고, 최종 보고 시 검증 근거를 확인할 수 있도록 제공한다.

사용자 허락 없이 기존 시트의 열을 추가하거나 변경하지 않는다.

### 5.2 검증과 수신 가능성 구분

공식 페이지에서 이메일을 확인했다는 사실과 이메일이 실제로 수신 가능하다는 사실은 다르다.

메일 서버나 수신 가능성을 확인하지 않았다면 `이메일 수신 가능 검증 완료`라고 주장하지 않는다.

HTTP 오류, 리다이렉트, 도메인 불일치, 오래된 정보가 있으면 확인 불가로 표시하고 추측하지 않는다.

### 5.3 중복 제거

중복 검사는 다음 순서로 수행한다.

1. 이메일 주소
2. 공식 홈페이지 도메인
3. 단체명 + 국가·지역
4. 동일 단체의 지점 또는 별도 법인 여부

기존 `email` 탭 전체와 이번 실행에서 확보한 후보 목록을 모두 비교한다. 반대 채널인 `ig` 탭도 아래 규칙에 따라 반드시 확인한다.

같은 단체의 다른 지점은 공식적으로 구분되는 경우에만 별개 리드로 인정한다.

기존 데이터와 충돌하면 임의로 덮어쓰지 않는다.

**기존에 수집된 리드를 다시 추가해서 신규 실적으로 계산하지 않는다.**

#### 양방향 교차 채널 중복 검사 (email ↔ ig)

- 매 실행 시작 시 `email` 및 `ig` 탭의 전체 기존 데이터와 발송 기록을 읽고, 이번 실행 후보 목록도 함께 비교한다. 어느 한 탭이라도 접근·확인이 불가능하면 교차 검증 완료로 처리하지 않고 신규 입력을 보류하여 보고한다.
- 공식 단체명(대소문자·공백·기호·표기 차이 정규화) + 국가·지역, 공식 홈페이지 도메인(프로토콜·www·경로 제거 및 리다이렉트 확인), 공식 홈페이지와 연결된 이메일·인스타그램 계정을 교차 확인한다. 공유 도메인이나 유사 명칭만으로 동일 단체라고 단정하지 않는다.
- 같은 단체의 지점·별도 법인은 공식적으로 구분되고 독립적인 영업 대상임이 확인된 경우에만 별개 리드로 인정한다. 동일성이 불명확하면 `보류`로 분류한다.
- 대상 탭에 이미 존재하거나 이번 후보와 중복된 리드는 제외한다. 반대 탭에 이미 존재하는 동일 단체는 `교차 채널 중복`으로 기록하고 기본적으로 신규 입력 및 신규 실적에서 제외한다. 아직 연락하지 않은 단체를 다른 채널에도 등록할 필요가 있다면 사용자 명시 승인 후에만 별도 채널 리드로 등록하며, 신규 단체 수와 구분하여 보고한다.
- `email`의 1·2·3차 이메일(G~I)과 `ig`의 1·2차 DM(M~N)은 실제 헤더에 따라 확인한다. 어느 채널이든 발송·접촉 기록이 있으면 사용자 별도 승인 없이 신규 접촉 대상으로 분류하거나 다른 채널로 재접촉하지 않는다. 수신 거부·접촉 제외가 확인된 단체는 양쪽 채널 모두 영업 대상에서 제외한다.
- 각 배치 입력 직전에 양쪽 탭과 이번 실행에서 이미 저장한 리드를 다시 비교하고, 저장 후에도 양쪽 탭을 재조회하여 중복·발송 기록·기존 데이터 보존을 검증한다.
- 교차 채널 일치 여부, 상대 탭·행 번호, 일치 근거, 발송 여부, 제외·보류·승인 예외 사유를 작업 기록에 남긴다. 기존 열을 임의로 추가하지 않고, 상대 탭은 읽기 전용으로 취급한다. 수집 승인은 발송 승인과 별개다.

## 6. Google Sheets 입력 규칙

### 6.1 실제 시트 구조 우선

Google Sheets에 접근한 뒤 다음 정보를 먼저 읽는다.

- 대상 스프레드시트
- 대상 탭
- 실제 헤더
- 열 개수
- 마지막 데이터 행
- 기존 이메일·단체명·공식 도메인
- 발송 기록 열
- 기존 수식·서식·드롭다운

**문서의 기본 열 정의보다 실제 시트의 구조와 사용자가 확정한 열 매핑을 우선한다.**

### 6.2 하루상자 영업 DB의 현재 9개 열 구조

현재 사용 중인 `email` 탭의 구조는 다음과 같다.

| 열 | 이름 | 신규 수집 입력 기준 |
|---|---|---|
| A | 구분 | 단체 종류 |
| B | 이름 | 공식 단체명 |
| C | 지역 | 국가 및 지역 |
| D | 국내/해외 | 해외 |
| E | 연락처 | 공식 홈페이지 또는 Contact URL |
| F | 이메일 | 공식 대표 이메일 우선 |
| G | 1차 이메일 | 공란 |
| H | 2차 이메일 | 공란 |
| I | 3차 이메일 | 공란 |

G~I열은 추가 이메일 주소가 아니라 **1·2·3차 발송 기록용 열**이다.

수집 단계에서는 날짜, 상태, 발송 여부를 임의로 입력하지 않는다.

다른 스프레드시트를 사용하는 경우에는 해당 시트의 실제 헤더를 읽고 필요한 경우 사용자에게 열 매핑을 확인한다.

### 6.3 배치 입력

검증된 리드를 한 건씩 입력하는 대신 **가능한 한 큰 묶음으로 일괄 입력한다.**

권장 방식:

1. 검증 완료 리드를 임시 목록에 누적한다.
2. 20~50건 또는 도구가 안정적으로 처리할 수 있는 크기로 묶는다.
3. 기존 시트의 마지막 데이터 행 다음에 추가한다.
4. 입력 후 해당 범위를 다시 읽는다.
5. 저장 성공 건수를 확인한다.
6. 남은 목표가 있으면 다음 배치를 계속 처리한다.

배치 크기는 도구 제한과 안정성에 따라 조정한다.

**첫 번째 배치가 성공했다는 이유로 전체 작업을 종료하지 않는다.**

### 6.4 기존 데이터 보호

- 기존 행을 수정하지 않는다.
- 기존 수식·드롭다운·서식을 보존한다.
- 기존 열을 삭제하거나 재배치하지 않는다.
- 기존 발송 기록을 변경하지 않는다.
- 필요한 경우 기존 표·필터 범위를 신규 행까지 확장한다.
- 입력 직전에 마지막 데이터 행 및 양쪽 탭의 중복·발송 기록을 다시 확인한다.
- 동시 편집으로 충돌이 발생하면 재조회 후 안전하게 재시도한다.

### 6.5 저장 후 재검증

입력된 범위를 다시 읽어 다음 사항을 확인한다.

- 신규 행 개수
- 단체명과 이메일
- 공식 홈페이지 URL
- 국가 및 지역
- 양쪽 탭 및 이번 실행 후보와의 중복 여부
- G~I 발송 기록 공란 여부
- 기존 행의 보존 여부

**쓰기 요청이 성공했다는 응답만으로 입력 완료라고 판단하지 않는다.**

실제 시트에 저장된 값이 재조회되어야 `입력 완료`로 계산한다.

## 7. 준수 및 안전

- robots.txt, 사이트 이용약관, 접근 제한, 합리적인 요청 속도를 존중한다.
- 차단을 우회하거나 과도한 병렬 요청으로 사이트에 부하를 주지 않는다.
- 공개 업무용 연락처만 수집한다.
- 개인 연락처, 비공개 자료, 로그인 필요 자료는 제외한다.
- 개인정보 최소 수집 원칙을 지킨다.
- 국가별 이메일 마케팅 관련 규정을 고려한다.
- 수신 거부 요청을 받은 주소는 이후 영업 대상에서 제외한다.
- 확인되지 않은 활동 여부나 담당자 소속을 사실처럼 작성하지 않는다.
- 이메일 발송은 별도 승인 및 적법성 확인 후 수행한다.

**리드 수집 승인과 이메일 발송 승인은 별개다.**

## 8. 목표 건수 달성을 위한 지속 수집·중단 방지 규칙

### 8.1 목표 완료 조건

사용자가 지정한 수집 건수는 이번 실행의 목표 완료 조건이다.

예를 들어 신규 100건을 요청받았다면 다음 조건을 모두 충족해야 한다.

- 이번 실행에서 새롭게 확보한 리드 100건
- 기존 DB와 중복되지 않음
- 공식 업무용 이메일 확인
- 최근 12개월 활동 확인
- 하루상자 적합성 확인
- Google Sheets 입력 성공
- 저장 후 재조회 성공

**기존 DB의 100건이나 검증 전 후보 100건은 목표 달성으로 계산하지 않는다.**

### 8.2 필수 실행 순서

1. **목표 고정:** 사용자 요청 건수를 신규 검증·저장 목표로 설정한다.
2. **기존 DB 확인:** `email`과 `ig` 전체 기존 데이터 및 발송 기록을 읽고 중복 기준을 준비한다.
3. **대량 후보 수집:** 목표의 약 2배 이상을 초기 후보 풀로 확보한다.
4. **일괄 검증:** 공식 이메일, 최근 활동, 적합성, 출처를 검증한다.
5. **중복 제거:** 양쪽 탭 및 이번 실행 후보와 비교하고 교차 채널 중복을 제외한다.
6. **배치 입력:** 검증 완료 리드를 Google Sheets에 추가한다.
7. **저장 재조회:** 입력된 행과 발송 기록 공란 여부를 확인한다.
8. **부족분 재탐색:** 목표에 미달하면 국가·지역·단체 유형·검색어를 변경한다.
9. **반복:** 목표 달성 또는 실제 실행 불가 사유 발생 전까지 반복한다.
10. **최종 보고:** 실제 저장·검증 결과를 기준으로 보고한다.

### 8.3 조기 종료 방지

다음 이유만으로 작업을 종료하지 않는다.

- 첫 번째 검색이 완료됨
- 첫 번째 국가의 조사가 끝남
- 첫 번째 입력 배치가 성공함
- 1~3건을 추가함
- 연결 테스트가 성공함
- 특정 검색어에서 후보가 부족함
- 수집에 시간이 걸림

한 국가에서 후보가 부족하면 사용자 지정 지역 안의 다른 국가를 조사한다.

한 단체 유형에서 후보가 부족하면 다른 유형을 조사한다.

**검증된 후보가 더 있고 작업을 계속할 수 있다면 가능한 범위에서 수집·검증·입력을 이어간다.**

단, 목표 달성을 위해 출처 검증 기준을 낮추거나 이메일을 추측하지 않는다.

### 8.4 중간 보고 최소화

사용자가 `100건 추가 후 보고`, `완료 전 보고 금지`, `중간 보고하지 마`라고 요청한 경우 다음 규칙을 적용한다.

- 일반적인 진행 상황 보고를 생략한다.
- 검색 결과를 조금 확보했다는 이유로 보고하지 않는다.
- 첫 번째 입력 배치가 성공해도 계속 작업한다.
- 가능한 한 목표 건수를 달성한 뒤 한 번에 보고한다.
- 작업을 실제로 계속할 수 있는 동안에는 결과 보고를 위해 임의로 중단하지 않는다.

**단, 중간 보고 금지 지시는 시스템의 실행 시간이나 도구 호출 한도를 늘리지 않는다.**

실행이 실제로 종료되어야 한다면 완료되지 않은 작업을 완료했다고 주장하지 않는다.

### 8.5 실제 중단 사유

목표 미달 상태에서 종료해야 한다면 구체적인 사유를 기록한다.

예시:

- 도구 호출 또는 실행 한도 도달
- 인증·접근 권한 상실
- Google Sheets 쓰기 실패 및 복구 불가
- 공식 사이트의 접근 제한
- 법적·정책적 제약
- 사용자 조건을 충족하는 추가 후보를 합리적인 탐색 확장 후에도 확보하지 못함

단순히 `건수가 많다`, `시간이 걸린다`, `일부 완료했다`는 설명만으로 조기 종료를 정당화하지 않는다.

실제 한계가 발생했다면 이를 숨기지 않는다.

### 8.6 중단 후 재개

목표에 도달하지 못하고 실행이 종료되는 경우 다음 정보를 남긴다.

- 최초 요청 건수
- 이번 실행에서 신규 저장·재조회 성공한 건수
- 남은 목표 건수
- 마지막 정상 저장 행
- 이미 조사한 국가·검색 범위
- 검증 완료했지만 저장하지 못한 후보
- 제외·보류 후보와 사유
- 다음 실행에서 이어갈 검색 전략

후속 실행 시 기존에 저장된 리드를 다시 신규 실적으로 계산하지 않는다.

**이전 실행의 완료 상태를 확인하고 중복 없이 이어서 진행한다.**

## 9. 대량 수집 성능 최적화 규칙

### 9.1 개별 검색보다 일괄 처리 우선

비효율적인 방식:

1. 단체 1곳 검색
2. 이메일 확인
3. 시트에 1행 입력
4. 결과 보고
5. 작업 종료

권장 방식:

1. 여러 국가·단체 유형에서 후보 200곳 이상 탐색
2. 후보 목록 정리
3. 기존 DB와 1차 중복 제거
4. 공식 이메일 및 최근 활동 일괄 검증
5. 검증 완료 100곳 확보
6. 20~50건씩 배치 입력
7. 전체 입력 범위 재조회
8. 최종 보고

단, **200개 후보를 반드시 모두 확보해야만 첫 입력을 시작하는 것은 아니다.** 충분한 검증 완료 리드가 확보되면 먼저 안전하게 저장하고, 나머지 목표를 계속 조사할 수 있다.

### 9.2 검증 우선순위 최적화

시간을 절약하기 위해 다음 순서로 후보를 검증한다.

1. 기존 DB와 중복 여부
2. 공식 홈페이지 존재 여부
3. 공식 대표 이메일 존재 여부
4. 최근 12개월 활동 여부
5. 하루상자 적합성
6. 출처 기록 완성

중복이거나 공식 이메일이 없는 후보에 불필요한 추가 조사를 반복하지 않는다.

### 9.3 국가별 수집 균형

사용자가 특정 국가를 지정하지 않았다면 한 국가에만 집중하지 않는다.

다만 **모든 국가에서 동일한 수량을 수집할 필요는 없다.**

공식 홈페이지 접근성, 영어 업무 연락 가능 여부, 최근 활동, 서비스 적합성을 고려해 검증 성공률이 높은 국가에 조사 자원을 우선 배분한다.

### 9.4 검색 실패 시 전략 변경

동일 검색어에서 유효 후보가 반복적으로 나오지 않으면 다음을 변경한다.

- 국가
- 도시·지역
- 단체 유형
- 행사 키워드
- 연도
- 공식 홈페이지 검색 방식

검색 결과가 부족하다는 이유로 출처 기준을 완화하지 않는다.

### 9.5 실제 처리량 관리

다음 수치를 구분하여 기록한다.

- 검색된 후보 수
- 중복 제외 수 (동일 채널·교차 채널 구분, 접촉 이력 및 승인 예외 별도 기록)
- 이메일 미확인 수
- 활동 미확인 수

## 11. 최종 완료 기준

다음 조건을 모두 충족해야 작업을 완료로 판단한다.

- [ ] 사용자가 요청한 신규 리드 수량을 확보했다.
- [ ] 모든 리드의 공식 홈페이지를 확인했다.
- [ ] 모든 리드의 공개 업무용 이메일 출처를 확인했다.
- [ ] 모든 리드의 최근 12개월 활동을 확인했다.
- [ ] 모든 리드가 하루상자 제안 대상에 적합하다.
- [ ] 양쪽 탭 및 이번 후보와의 중복 검사, 발송 기록 검사 및 교차 채널 제외·승인 예외 기록을 완료했다.
- [ ] Google Sheets에 신규 행으로 저장했다.
- [ ] 기존 데이터와 발송 기록을 변경하지 않았다.
- [ ] 저장된 행을 다시 읽어 값과 건수를 확인했다.
- [ ] 최종 보고에서 실제 검증·저장 결과를 정확하게 설명했다.

**최종 원칙:**

> 목표는 검색 결과 100개를 나열하는 것이 아니라, 공식 출처가 검증된 신규 리드 100개를 실제 Google Sheets에 안전하게 저장하고 재조회하는 것이다.
>
> 속도를 높이기 위해 수집·검증·입력 과정을 배치화하되, 정확성과 중복 방지 원칙은 유지한다.
>
> 단일 실행의 기술적 한계 때문에 목표 수량 달성을 보장할 수는 없다. 실제 한계가 발생하기 전까지 가능한 작업을 수행하고, 한계가 발생하면 완료 수량과 미완료 사유를 정확히 기록한다.
>
> **사용자의 별도 승인 없이 이메일을 발송하지 않는다.**
